# Встановлення CoreCommerce на веб-хостинг

Версія рушія: **1.0.0**  
Вимоги: PHP 8.1+ (Рекомендовано PHP 8.3), MySQL 5.7+ / MariaDB 10.5+, mod_rewrite (Apache) або URL rewriting (Nginx)

---

## Крок 1 — Завантаження файлів на хостинг

Завантажте всі файли проєкту на хостинг у **домашню директорію сайту** (наприклад `public_html/`, `www/`, `htdocs/` — залежить від хостингу).

> **Важливо:** документ-рут (Document Root) вашого домену має вказувати на підпапку **`public/`**, а не на корінь проєкту. Якщо ваш хостинг дозволяє змінити Document Root через панель керування (cPanel, ISPManager, DirectAdmin) — зробіть це. Якщо ні — дивіться Додаток А в кінці цього файлу.

Структура після завантаження:
```
/home/user/site.com/          ← корінь проєкту
    app/
    config/
    lang/
    plugins/
    public/                   ← сюди має вказувати Document Root домену
        index.php
        .htaccess
        ...
    resources/
    storage/
    vendor/
    .env
    ec30.sql
    ...

---

## Крок 2 — Створення бази даних

1. В панелі керування хостингом (cPanel → MySQL Databases або аналог):
   - Створіть **нову базу даних** (наприклад `site_shop`)
   - Створіть **нового користувача** з надійним паролем
   - Надайте користувачу **всі права** на цю базу даних

2. Імпортуйте початкову структуру та дані:
   - Через **phpMyAdmin**: Виберіть БД → вкладка «Імпорт» → завантажте файл `ec30.sql` → «Виконати»
   - Або через SSH: `mysql -u user -p site_shop < ec30.sql`

## Крок 3 — Налаштування .env

Якщо файл .env відсутній — система автоматично при першій загрузці зкопіює .env.example → .env

Відредагуйте `.env.example`:

```ini
# ─── База даних ───────────────────────────────
DB_HOST=localhost
DB_PORT=3306
DB_NAME=site_shop          # ← ваша БД з Кроку 3
DB_USER=site_user          # ← ваш користувач БД
DB_PASS=strong_password    # ← ваш пароль БД

# ─── Додаток ──────────────────────────────────
APP_ENV=production
APP_DEBUG=false            # ← ОБОВ'ЯЗКОВО false на продакшні!
APP_URL=https://site.com   # ← ваш реальний домен (без слеша в кінці)

# ─── SMTP-пошта ───────────────────────────────
MAIL_HOST=smtp.gmail.com   # ← або ваш поштовий провайдер
MAIL_PORT=587
MAIL_USER=your@gmail.com
MAIL_PASS=app_password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=no-reply@site.com
MAIL_FROM_NAME="Назва магазину"
```

> **Примітка:** пошту також можна налаштувати пізніше прямо в адмінці: **Налаштування → Пошта**. Значення з адмінки завжди мають пріоритет над `.env` або .env.example.

## Крок 4 — Права доступу на папки

Папка `storage/` і всі вкладені директорії мають бути доступні для запису веб-сервером:

```bash
chmod -R 755 storage/
chmod -R 755 public/uploads/
```

Якщо на хостингу потрібно 777:
```bash
chmod -R 777 storage/
chmod -R 777 public/uploads/
```

Мінімально необхідні папки для запису:
```
storage/cache/
storage/logs/
storage/backups/
storage/local_updates/
storage/temp/
public/uploads/
```

## Крок 5 — Перевірка .htaccess

Файл `public/.htaccess` вже присутній у дистрибутиві й налаштований правильно. Переконайтесь, що на хостингу увімкнено `mod_rewrite`:

```apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [L]
```

Якщо сайт віддає **404 на всі сторінки крім головної** — `mod_rewrite` вимкнений або `AllowOverride None` в конфігурації Apache. Зверніться до підтримки хостингу.

## Додаток А — Якщо Document Root не можна змінити

Якщо хостинг не дозволяє змінити Document Root і домен вказує на корінь проєкту (де лежить `app/`, `config/` тощо) — додайте файл `.htaccess` в **корінь проєкту** (не в `public/`) з таким вмістом:

```apache
RewriteEngine On
RewriteRule ^$ public/ [L]
RewriteRule ^(.*)$ public/$1 [L]
```

> **Увага:** цей варіант менш безпечний — корінь проєкту доступний через веб-сервер. По можливості завжди використовуйте Document Root → `public/`.

## Додаток Б — Nginx (замість Apache)

Якщо ваш хостинг використовує Nginx, додайте до конфігурації блоку `server {}`:

```nginx
root /home/user/site.com/public;
index index.php;

location / {
    try_files $uri $uri/ /index.php?$query_string;
}

location ~ \.php$ {
    fastcgi_pass unix:/run/php/php8.1-fpm.sock;
    fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    include fastcgi_params;
}

location ~ /\. {
    deny all;
}
```

## Усунення проблем

| Симптом | Причина | Рішення |
|---|---|---|
| Біла сторінка / 500 | Помилка PHP | Тимчасово увімкніть `APP_DEBUG=true` в `.env`, перевірте `storage/logs/` |
| 404 на всіх сторінках | `mod_rewrite` вимкнений | Зверніться до підтримки хостингу |
| "Table not found" | БД не імпортована | Повторіть Крок 3 |
| Пошта не відправляється | Неправильні SMTP дані | Перевірте Налаштування → Пошта в адмінці |
| Помилка підключення до БД | Неправильний `.env` | Перевірте `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` |
